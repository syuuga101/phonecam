# タスク: 受信のタイムアウトと上限（監査 #7、#8）

監査報告: `docs/audit/2026-11-15-audit.md`。指摘はまずコードで確かめる。
（#10・#14・#17・#18・#20・#22 は Claude 側のブランチ `claude/audit-ui` と `claude/audit-ios` で対応するので、この PR では触らない）

## やること
- **#7** 受信のタイムアウト: `read_exact` がタイムアウトを無期限に再試行しないようにする。認証、受信開始、フレームの途中、それぞれに期限を設ける（例: 認証 10 秒、無通信 5 秒）。期限が来たら切断し、再接続か USB/Wi-Fi の切り替えに進む。usbmux でも同じようにする。
- **#8** 受信の上限: パケットの種別ごと・認証段階ごとに長さの上限を設ける。usbmux が宣言する長さにも上限を設ける。音声は、変換する前にサンプル数と変換後の見込みサイズを確かめる。

## テスト
- #7・#8 は pytest でテストする。偽のソケットを使い、無応答、巨大な長さ、HTML の名前、ミュートの組み合わせを確かめる。
- CI（pytest / build / qt-screenshots / Build iOS）がすべて成功すること。

## 守ること
- 接続の暗号化（別の PR `codex/secure-link`）と、Windows の権限まわり（別の PR `codex/win-hardening`）には手を出さない。
- USB を優先して接続する挙動を変えない。
