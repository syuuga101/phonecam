# タスク: 実機で fps の落ち込みを測って直す（Codex向け）

## 背景
- iPhone 13 → USB → Windows 受信アプリ（PySide6 / PyAV d3d11va / softcam）の構成で、PC 側の出力が 60fps に届かず、48fps 前後になることがある。
  - iPhone の送出は 60fps、USB の取りこぼしは 0。
- v2.5.0 で、状態ページに「iPhone / 受信 / 出力」の fps を出すようにした。あわせて、GUI 更新の間引き・左右反転の高速化・プレビューの無駄削減を入れた。
- それでも原因は確定していない。クラウドの環境には Windows・GPU・iPhone が無いため。
- あなた（Codex）はユーザーの Windows PC で動けるので、本物の iPhone とつないで実測できる。

## やること
1. **計測の仕組みを入れる**
   - 環境変数 `PHONECAM_PROFILE=1` のときだけ、受信 → デコード → 色変換・GPU→CPU コピー → 出力（左右反転・合わせ方） → softcam 送信 → プレビュー変換の各段の所要時間を測る。
   - 結果を 1 秒ごとに `%APPDATA%\PhoneCam\profile.log` に出す（平均・p95・最大）。
   - BacklogGuard の間引き回数と、FrameMailbox で上書きされた回数も出す。
   - GUI スレッドの 1 tick あたりの時間と、Python の GIL 待ちも出す（可能なら）。
   - 通常時の性能には影響させない。
2. **実測する**
   - 1920x1080・60fps、USB で次の 3 つの状況を測る。
     - アプリを最小化
     - 接続ページを表示（プレビューあり）
     - 状態ページを表示
   - 結果を PR の説明に表で書く。
   - カメラを 2 台にした場合も、できれば測る。
3. **原因を直す**
   - 測った結果から、16.7ms を超えている段を特定して直す。
   - 例: d3d11va からの取り出しを NV12 のまま softcam へ渡す、色変換をスレッドの外へ、numpy のコピー削減、出力をデコードと別スレッドにする、GIL を離す C 拡張の使い方、Qt の描画、など。
   - 映像の見た目（色・向き・合わせ方）を変えないこと。
   - USB・60fps で出力が安定して 59〜60fps になることを目標にする。
4. **確認**
   - 直したあと、同じ表で再計測した結果を PR に書く。

## 守ること
- 始める前に `git merge origin/main` で最新を取り込む（v2.9.0 以降。Tk は削除済み）。
- UI の見た目は変えない（UI は Claude 担当）。計測の表示が必要なら、状態ページにテキストを1行足す程度にする。
- exe のビルドは最後に 1 回だけでよい。
- 確認できたこと・できなかったことを、PR の説明に日本語で書く。
