# タスク: Wi-Fi 通信の暗号化と相互認証（監査 #1〜#4、#9、#19、#21）

監査報告: `docs/audit/2026-11-15-audit.md`。指摘はまず自分でコードを読んで確かめ、誤りがあれば PR に書く。

## 方針（Opus 決定）
- **目標は「USB で最小遅延」を壊さないこと。** USB（usbmux＝ケーブル直結）は暗号化しない。ただし下の鍵による相互認証は行う。Wi-Fi は必ず暗号化する。
- **固定 PIN を回線に流さない。** 6 桁コードは「その接続の鍵交換から作る照合コード」に変える。
- **長期鍵**: PC と iPhone はそれぞれ X25519 の長期鍵を 1 つ持つ。
  - iOS: CryptoKit。秘密鍵は Keychain に保存する。
  - Windows: `cryptography`。秘密鍵は DPAPI か Windows 資格情報で保護する。
  - ペアリングで相手の公開鍵を保存する（ピン留め）。
- **ペアリング（2 通り。今の UX は変えない）**
  1. **コード方式**（Wi-Fi 一覧の「つなぐ」＋ v2.12.0 のポップアップ）
     - 両者が一時鍵で ECDH し、transcript ハッシュから 6 桁を導出する。
     - iPhone はその 6 桁をポップアップと設定画面に出し、PC はユーザーが入力した 6 桁と照合する。
     - 一致したら、暗号化した経路で長期公開鍵を交換して保存する。
     - 試行回数の制限は今の仕組みを流用する。コードは毎回変わり、使い捨てにする。
  2. **QR 方式**
     - QR に「PC 長期公開鍵のフィンガープリント＋一回限りトークン＋接続先」を入れる。
     - iPhone はフィンガープリントを検証した相手にだけ公開鍵を渡す。PIN は送らない。
- **通常接続**
  - 静的鍵（ペアリング済み）と一時鍵を組み合わせたハンドシェイク（Noise IK/XX 相当）でセッション鍵を導出する。
  - 映像・音声・制御のすべてのパケットを ChaCha20-Poly1305 か AES-GCM で暗号化する。nonce は方向別のカウンタにする。
  - 映像ソケット・音声ソケット・制御はすべて同じセッションに結び付ける。音声チャンネルは、映像セッションから出たトークンで照合する（#4）。
  - 映像接続の世代が変わったら、旧音声ソケットを必ず閉じる（#4）。
- **認証前の扱い（#2）**
  - Bonjour は候補を列挙するためだけに使う。
  - 認証が完了するまで、設定送信・デコーダーへの投入・録画などの制御をしない。
  - 機器 ID が欠けた応答を旧機種互換として通す処理は廃止する。
- **DoS 対策（#9、#19）**
  - 未認証の接続は、送信元ごとに 1 本、全体で 4 本までにする。
  - 認証には期限（例: 10 秒）を設ける。
  - 受理済みの接続も、ロックアウトに入ったら切る。期限切れのエントリは掃除する。
  - QR の一時リスナーは、QR に載せたインターフェースだけで待ち受ける。
- **保存（#21）**
  - Windows の settings には公開鍵とフィンガープリントだけを置く。旧 PIN は移行後に削除する。
  - 接続ログでは、シリアルと IP を伏せ字にする。
- **互換性**
  - プロトコルを v2.0 にする。旧版の相手とは Wi-Fi でつながず、「両方を最新にしてください」と表示する。
  - USB では、旧版との接続を 1 版だけ許してよい。
  - 既存の登録は、初回の接続時に再ペアリングを促す。
  - `docs/PROTOCOL.md` と `SECURITY.md` を更新する。
- **性能**: 1080p60・20Mbps で、暗号化による遅延の増加は 1ms 未満を目標にする。PC 側で計測し、PR に書く。

## テスト
- Windows: ハンドシェイク、改ざん検出、リプレイ拒否、旧 PIN を送らないこと、認証前にデコーダーを呼ばないこと、音声トークンの照合。
- iOS: `ios/Tests` に、純粋ロジック（鍵導出・nonce・照合コード）のチェックを足し、`ios.yml` で実行する。
- CI（pytest / build / qt-screenshots / Build iOS）がすべて成功すること。

## 守ること
- USB の接続手順（link.py の USB 優先、5557 プローブ）を壊さない。
- 実機で確かめていないことは、PR に「未検証」と書く。
