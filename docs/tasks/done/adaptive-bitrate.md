# タスク: 通信が不安定なときに画質を自動で上げ下げする（Codex向け）

## ゴール
Wi-Fi が不安定なとき、映像が固まったり遅れたりするのを減らす。
通信の状態に合わせて、ビットレート（と必要なら解像度・fps）を自動で下げ、回復したら戻す。

## 現状
- iPhone は TCP で送信し、詰まったときはキーフレーム以外を捨てている（ios/PhoneCam/StreamServer.swift）。
- ビットレートは PC から指定する固定値（2〜50 Mbps）。
- 状態ページに「取りこぼしたフレーム（iPhone / 通信）」がある。

## やること
1. **iPhone 側で詰まりを測る**
   - 送信待ちの量、送信にかかった時間、捨てたフレーム数から、混み具合を毎秒判断する。
   - PC からの ping/pong の RTT も使ってよい。
2. **レートを自動で変える**
   - 混んだら VideoToolbox のビットレートを段階的に下げる（下限は設定の 30% 程度）。
   - 安定したらゆっくり戻す（上限は PC で指定した値）。
   - 必要ならキーフレームを要求する。
3. **PC 側**
   - 接続ページか画質ページに「自動で画質を調整（Wi-Fi のとき）」のスイッチを置く。既定は Wi-Fi のときオン、USB のときオフ。
   - 状態ページに、今の実ビットレートと自動調整中かどうかを出す。
4. **プロトコル**
   - control JSON に設定を足し、status JSON に実ビットレートを足す。docs/PROTOCOL.md を更新する。
   - 古い iPhone アプリ・古い PC アプリとつないでも壊れないこと（知らないキーは無視）。

## 守ること
- USB では今の低遅延の挙動を変えない。
- 始める前に `git merge origin/main`。

## 確認
- Windows で exe をビルドし、iPhone 実機で、Wi-Fi の電波が弱い場所や、帯域を絞った状態で試す。
- iOS は CI（Build iOS）で確認する。
- 確認できたこと・できなかったことを PR の説明に日本語で書く。
