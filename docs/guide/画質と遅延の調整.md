# 画質と遅延の調整

## まずはこの設定

| 項目 | おすすめ |
|---|---|
| 接続 | **USB**（Wi-Fi より安定して、遅延も小さい） |
| iPhoneから送る解像度 / fps / ビットレート | 1080p / 60fps / 20Mbps |
| 出力サイズ（仮想カメラ） | 1920×1080 |
| 露出・ホワイトバランス・フォーカス | **マニュアル／固定**（配信中に明るさや色が勝手に変わりません） |
| コーデック | H.264（USB ならこれで十分） |
| ハードウェアデコード | オン（既定） |

目標の遅延は、USB・1080p60 で **おおよそ 50〜100ms** です（環境によります）。

## 映像が乱れる・固まる

- **USB** を使ってください。
- ビットレートを下げます。
- Wi-Fi のときは、コーデックを **HEVC** にすると、同じ画質を少ないデータ量で送れて、乱れにくくなります（PC の負荷は少し増えます）。
- 受信アプリは、固まったときに自動でキーフレームを再要求します。

## 遅延を小さくしたい

- USB でつなぐ
- ビットレートを上げすぎない
- PC の負荷を下げる（出力サイズを小さく、ハードウェアデコードをオン、fps を下げる）
- OBS のソースのバッファリングを無効にする
- 音声は [音声（iPhoneのマイク）を使う](%E9%9F%B3%E5%A3%B0%EF%BC%88iPhone%E3%81%AE%E3%83%9E%E3%82%A4%E3%82%AF%EF%BC%89%E3%82%92%E4%BD%BF%E3%81%86.md) を見てください

H.264 と HEVC の遅延は、ほぼ同じです。違うのは通信量とデコードの負荷です。

## 映像が暗い・ちらつく

照明のちらつきは、シャッター速度を地域の電源周波数に合わせると消えます。露出を **マニュアル** にしてから設定してください。

- 東日本（50Hz）: **1/50** か **1/100**
- 西日本（60Hz）: **1/60** か **1/120**

## 向きと出力の形

- 向き（映像 > 向き）: **自動**（iPhone を縦に持てば縦映像）/ **横**（常に 1920×1080）/ **縦**（常に 1080×1920）
- 出力の形: 仮想カメラのサイズを固定します。既定は「向きの設定に合わせる」。
- 合わせ方: **余白を付けて全体を表示**（既定）/ **はみ出す部分を切り取って埋める**

OBS は仮想カメラの最初のサイズを覚えるので、途中でサイズが変わると映像が止まります。そのためサイズを固定し、向きが変わっても止まらないようにしています。**出力サイズ・出力の形・向きを変えたときだけ**、OBS はソースを一度「非表示→表示」、Discord はカメラを一度オフ→オンにしてください。

## 発熱とバッテリー

- 長時間使うときは、iPhone の **設定 > バッテリー > 充電最適化** で充電上限を 80% にして、風通しの良い場所に置きます。
- 「状態」タブに温度が「高い」「危険」と出たら、fps を 30 に下げるか、エフェクトをオフにします。
- **iPhoneの画面を真っ黒にする** をオンにすると、発熱とバッテリー消費を抑えられます（配信は続きます）。「操作がないと自動で黒くする」も選べます。
- **カメラを動かすタイミング**（接続・映像タブ）:
  - **使われているときだけ（自動）**（既定）: OBS や Discord が PhoneCam を開いている間だけ iPhone のカメラが動きます。
  - **接続中ずっと**: 接続している間は常に動かします。
  - **手動**: **開始** を押したときだけ動かします。
  - 自動判定は、出力先が「PhoneCam（専用カメラ）」のときだけ使えます。

## 遅延を測る

「状態」タブに、**iPhone処理 / 通信 / PC処理 / 合計** が表示されます（カメラの露光や OBS の表示までの時間は含みません）。実際の遅延を測るには、**計測用タイマーを開く** を押し、カメラをそのタイマーに向けて、OBS のプレビューに映るタイマーと実物のタイマーを一緒にスクリーンショットします。2 つの差が遅延です。

## エフェクト

- **背景**: オフ / ぼかし / 切り抜き(緑)。強さと品質（速度優先 / バランス）を選べます。処理は iPhone で行います。
- **色調整**: 明るさ・コントラスト・彩度・シャープネス。「リセット」で戻ります。
