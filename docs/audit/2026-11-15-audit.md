# PhoneCam バグ・セキュリティ監査

2026年11月15日（日本時間）

公開版 [v2.12.0](https://github.com/syuuga101/phonecam/releases/tag/v2.12.0)（`89b733e`）と、PR #13 を取り込んだ [main](https://github.com/syuuga101/phonecam/tree/0fae40738493ad49116a8970a13d0d07735708af)（`0fae407`）を対象にしました。公開版から main までのアプリ差分は Windows のプレビュードック関連です。PR #14 の SideStore 記事は配布手順の参考にしました。

**製品と配布経路の検出事項は22件（高6件、中13件、低3件）です。** 優先度は修正順の目安です。「再現」はローカルでの模擬入力・画面検証、「コード確認」は実装から確認した経路、「要実機」は発生条件や影響を端末や Windows VM で詰める項目です。

## 高

### 1. Wi-Fi の映像・音声・操作・PIN が平文で流れる

**コード確認｜iPhone・Windows｜v2.12.0 / main**

iPhone の配信は TLS を無効にした TCP 接続です。Windows は6桁の PIN を制御 JSON で送ります。経路を観測できる機器から映像・マイク音声・PIN を読み取れます。取得した PIN は、変更されるまで別接続で使えます。通信経路を操作できる場合は、制御の改変も可能です。PIN を知る接続には録画開始・停止などの制御も許可されます。

暗号化と両方向の端末認証を同時に導入し、セッション単位で鍵を導出してください。映像・音声・制御をすべて認証済みの接続に結び付けます。

根拠 [iOS リスナー](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/ios/PhoneCam/StreamServer.swift#L166) · [Windows 認証送信](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/windows/phonecam/core/link.py#L539) · [録画制御](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/ios/PhoneCam/Model/AppModel.swift#L371)

### 2. 偽の iPhone に保存済み PIN を送信し、認証前から映像をデコードする

**再現｜Windows｜v2.12.0 / main**

発見時の Bonjour UUID は署名されていません。登録済みと同じ UUID を通知した機器のアドレスが優先され、Windows は TCP 接続直後に PIN と設定を送信します。受信側では認証成功より先に H.264/HEVC がデコーダーに渡ります。機器 ID が欠落した応答を旧機種互換で通す処理もあります。

模擬ソケットで、保存 PIN が最初の送信に含まれ、認証が通っていない状態でデコーダーが呼ばれることを確認しました。登録済み機器と同じ ID の広告が優先されることも確認しました。デコーダーへの到達を確認した段階です。

Bonjour は候補の列挙に使い、接続先を証明するまで PIN・設定の送信とメディア処理を止めてください。

根拠 [Bonjour マージ](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/windows/phonecam/core/wireless.py#L309) · [接続先選択](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/windows/phonecam/core/link.py#L234) · [受信ループ](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/windows/phonecam/core/link.py#L796) · [機器 ID の扱い](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/windows/phonecam/core/cameras.py#L97)

### 3. 偽の QR に iPhone が現在の PIN を渡す

**コード確認｜iPhone・Windows｜v2.12.0 / main**

iPhone は QR に入った PC 名を表示し、利用者の確認後にそこに書かれたアドレスへ TCP 接続します。現在の PIN、機器 ID、機種、IP アドレスを相手へ送り、成功応答には `ok: true` を使います。QR 自体を偽装するか、経路上で応答を差し替えられる場合、正規 PC への登録を装って PIN を取得できます。取得した PIN で Wi-Fi 接続するには、iPhone の Wi-Fi 許可とネットワーク到達性も必要です。

QR に一時公開鍵を入れ、双方の画面で短い照合コードを確認する方式へ変更し、通常の配信用 PIN を QR の宛先へ送らない設計にしてください。

根拠 [確認画面](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/ios/PhoneCam/Views/WirelessScanner.swift#L15) · [PIN を含む要求](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/ios/PhoneCam/WirelessPairing.swift#L99) · [応答判定](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/ios/PhoneCam/WirelessPairing.swift#L161)

### 4. 映像接続を別の PC に切り替えた後、旧 PC の音声接続が残り得る

**コード確認・要実機｜iPhone｜v2.12.0 / main**

マイク用ポートは接続を受け付ける時点で送信元 IP を照合します。映像接続を置き換える処理は旧映像ソケットをキャンセルしますが、通常切断時に音声ソケットを閉じるコールバックは呼びません。旧音声ソケットは、新 PC が音声チャンネルを開いて置き換えるまで残る経路があります。新 PC が音声を使わない設定のときに、旧 PC にマイク音声が送られ続ける可能性があります。Wi-Fi から USB への切替も確認対象です。

映像接続の世代が変わるたびに旧音声接続を失効させ、音声チャンネルは IP と併せてセッション鍵または結び付け用トークンで照合してください。

根拠 [音声の接続元照合](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/ios/PhoneCam/StreamServer.swift#L215) · [既存接続の置換](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/ios/PhoneCam/StreamServer.swift#L266) · [通常切断時の音声終了](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/ios/PhoneCam/Model/AppModel.swift#L349)

### 5. 管理者セットアップのジョブを、照合後に差し替えられる

**再現｜Windows｜v2.12.0 / main**

管理者ヘルパーはユーザーの一時フォルダーにある `job.json` の SHA-256 を照合し、そのパスをもう一度開いてジョブを読みます。2回の読み取りの間にファイルが置き換わると、別の内容が照合済みとして扱われます。ジョブは実行ステップと出力先を指定できます。管理者承認済みの実行中に、そのファイルを変更できるローカルプロセスが存在することが前提です。

ハッシュ計算直後にファイルを入れ替える模擬試験で、差し替え後の無害なステップと出力先が採用されました。管理者権限での攻撃コード実行は試していません。

検証と JSON 解釈を同じバイト列で行い、管理者側で許可する操作とその引数・出力先を固定してください。

根拠 [一時作業フォルダー](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/windows/phonecam_setup.py#L413) · [管理者ヘルパー呼び出し](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/windows/phonecam_setup.py#L1964) · [照合と再オープン](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/windows/phonecam_setup.py#L1209)

### 6. 仮想カメラの登録解除で、レジストリ由来の DLL を管理者権限で読み込む

**コード確認・要 VM｜Windows｜v2.12.0 / main**

`--unregister` は `HKCR\CLSID\…\InprocServer32` の値を取得し、その DLL を `regsvr32 /u` に渡します。HKCR はユーザー別とマシン全体の登録をマージしたビューです。管理者ヘルパーと同じ利用者の登録を差し替えられる構成では、解除を承認したタイミングで、攻撃者の DLL を管理者権限でロードする経路になり得ます。実機のレジストリ変更や昇格実行は行っていません。

管理者ヘルパーはマシン側の登録を明示して読み、アプリ管理下の DLL パスと正規のファイル内容を検証してから解除してください。

根拠 [登録パスの取得](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/windows/phonecam/core/softcam_reg.py#L123) · [解除処理](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/windows/phonecam/core/softcam_reg.py#L292) · [Microsoft の HKCR 仕様](https://learn.microsoft.com/en-us/windows/win32/sysinfo/merged-view-of-hkey-classes-root)

## テスト・配布物・調査の範囲

- **Windows テスト** — main とアプリコードが同じ PR #13 の GitHub Actions では pytest 199件、ビルド、Qt スクリーンショットが成功しています。監査時のローカル Windows／Python 3.13 では、全体テストを2回実行した際に `test_qt.py` の QApplication 後処理でプロセスが異常終了しました。同じコードの先行ローカル実行では199件が通過しており、終了時の不安定さを確認しています。配布 EXE のクラッシュはこの試験では立証していません。[GitHub Actions](https://github.com/syuuga101/phonecam/actions/runs/43693144572) · [テスト後処理](https://github.com/syuuga101/phonecam/blob/0fae40738493ad49116a8970a13d0d07735708af/windows/tests/test_qt.py#L15)
- **静的解析** — Bandit でアプリ・配布スクリプトを走査し、128件の機械的指摘のうち中優先度は3件でした。1件は QR リスナーの全インターフェース待受、2件はルーティング表検索文字列の誤検出です。Ruff の指定ルールでは33件の指摘があり、未定義名は検出されませんでした。例外チェーンや即時実行されるラムダ等の指摘は、単独の製品バグとして数えていません。両ツールの結果は上記のコードレビューと模擬試験で評価しました。
- **依存関係** — pip-audit はローカルで照合した直接・間接依存14件の PyPI パッケージについて登録済みの脆弱性を返しませんでした。ローカルホイールの実体は Qt 6.8.3、PyAV が報告した FFmpeg 9.0.2 です。ネイティブ部品の脆弱性はパッケージ検索だけでは網羅できないため、Qt 上流も照合しました。公開 EXE に含まれる全 DLL の部品表と、個々の CVE の到達性は未確定です。[Qt 上流の一覧](https://wiki.qt.io/List_of_known_vulnerabilities_in_Qt_products) · [FFmpeg のセキュリティ情報](https://ffmpeg.org/security.html)
- **配布物** — v2.12.0 の EXE と IPA の SHA-256 は、GitHub が返すアセットのダイジェストと一致しました。Windows EXE の署名と IPA のマニフェスト・entitlement は静的に検査しました。[公開リリース](https://github.com/syuuga101/phonecam/releases/tag/v2.12.0)
- **未検証** — iPhone 実機での Wi-Fi/USB、録画、音声切替、SideStore 再署名後の entitlement、Windows の管理者境界の実機動作、OBS・Discord、長時間の負荷試験は未実施です。コード変更・GitHub への指摘公開は行っていません。
